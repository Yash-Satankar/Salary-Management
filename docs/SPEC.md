## 2. Domain rules

1. **Salary** = annual gross base salary in the employee's local currency, stored as an **integer number of minor units** (`BIGINT`). Floats are never used for money.
2. **Currency is derived from country** by the server; clients never send a currency for employees. Each country has exactly one currency. The DB enforces the pairing (composite FK, §3).
3. **Currency exponent matters**: INR/USD/GBP/EUR/CAD/AUD/SGD have 2 minor digits; **JPY has 0**. All parsing and formatting uses the exponent from the `currencies` table. Converting a major-unit string such as `"1250000.50"` to minor units uses exact string/integer arithmetic, never `parseFloat`.
4. **Salary bounds**: `salaryMinor` is an integer > 0. The USD-equivalent must be ≤ 5,000,000. Validate in the service using FX rates.
5. **Employee code** is generated by the DB (`EMP-000001` …) and is immutable. **Email** is unique case-insensitively and stored lower-cased.
6. **Job title belongs to a department**. An employee's department is derived from the job title.
7. **Status**: `active` | `terminated`. Terminating sets `terminated_on` (≥ hire date, ≤ today). Terminated employees are read-only (edits → 409) and excluded from insights. There is no hard delete.
8. **Hire date** ≤ today + 90 days (to allow accepted offers).
9. **Salary history**: creating an employee writes the initial `salary_changes` row (previous = null). Any change to salary or country writes a row **in the same transaction** as the employee update. Changing country **requires** a new salary in the same request (422 otherwise), because the currency changes.
10. **Employment type**: `full_time` | `part_time` | `contract`.
11. **FX** is a static, dated reference table (`usd_per_unit`, `as_of`, `source`). Every USD figure in the API carries `fx.asOf` metadata, and every USD figure in the UI is labelled approximate.

## 3. Database schema (Kysely migrations)

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE currencies (
  code        CHAR(3) PRIMARY KEY,
  name        TEXT NOT NULL,
  minor_unit  SMALLINT NOT NULL CHECK (minor_unit BETWEEN 0 AND 3)
);

CREATE TABLE fx_rates (
  currency_code CHAR(3) PRIMARY KEY REFERENCES currencies(code),
  usd_per_unit  NUMERIC(20,10) NOT NULL CHECK (usd_per_unit > 0),
  as_of         DATE NOT NULL,
  source        TEXT NOT NULL
);

CREATE TABLE countries (
  code          CHAR(2) PRIMARY KEY,
  name          TEXT NOT NULL UNIQUE,
  currency_code CHAR(3) NOT NULL REFERENCES currencies(code),
  UNIQUE (code, currency_code)
);

CREATE TABLE departments (
  id   SMALLINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE job_titles (
  id            SMALLINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name          TEXT NOT NULL UNIQUE,
  department_id SMALLINT NOT NULL REFERENCES departments(id)
);

CREATE SEQUENCE employee_code_seq;

CREATE TABLE employees (
  id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  employee_code   TEXT NOT NULL UNIQUE
                  DEFAULT ('EMP-' || lpad(nextval('employee_code_seq')::text, 6, '0')),
  full_name       TEXT NOT NULL CHECK (char_length(full_name) BETWEEN 2 AND 120),
  email           TEXT NOT NULL,
  job_title_id    SMALLINT NOT NULL REFERENCES job_titles(id),
  country_code    CHAR(2) NOT NULL,
  currency_code   CHAR(3) NOT NULL,
  salary_minor    BIGINT NOT NULL CHECK (salary_minor > 0),
  employment_type TEXT NOT NULL CHECK (employment_type IN ('full_time','part_time','contract')),
  hire_date       DATE NOT NULL,
  status          TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','terminated')),
  terminated_on   DATE,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  FOREIGN KEY (country_code, currency_code) REFERENCES countries(code, currency_code),
  CHECK ((status = 'terminated') = (terminated_on IS NOT NULL)),
  CHECK (terminated_on IS NULL OR terminated_on >= hire_date)
);

CREATE UNIQUE INDEX employees_email_lower_uq ON employees (lower(email));
CREATE INDEX employees_active_country_idx  ON employees (country_code, job_title_id) WHERE status = 'active';
CREATE INDEX employees_status_name_idx     ON employees (status, full_name, id);
CREATE INDEX employees_job_title_idx       ON employees (job_title_id);
CREATE INDEX employees_full_name_trgm_idx  ON employees USING gin (full_name gin_trgm_ops);

CREATE TABLE salary_changes (
  id                     BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  employee_id            BIGINT NOT NULL REFERENCES employees(id) ON DELETE CASCADE,
  previous_salary_minor  BIGINT,
  previous_currency_code CHAR(3) REFERENCES currencies(code),
  new_salary_minor       BIGINT NOT NULL CHECK (new_salary_minor > 0),
  new_currency_code      CHAR(3) NOT NULL REFERENCES currencies(code),
  effective_date         DATE NOT NULL,
  reason                 TEXT CHECK (reason IS NULL OR char_length(reason) <= 200),
  created_at             TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX salary_changes_employee_idx ON salary_changes (employee_id, effective_date DESC, id DESC);
```

Reference data (currencies, fx_rates, countries, departments, job_titles) is inserted by a **migration**, not by the seed, so production always has it.

Write the Kysely `Database` interface by hand in `apps/api/src/db/schema.ts`. Configure `pg` to parse `BIGINT` (OID 20) to a JS `number`, with a guard that throws if the value is not `Number.isSafeInteger`. Leave `NUMERIC` as a string and convert it explicitly.

### Reference data

**Countries / currencies** (8): IN/INR, US/USD, GB/GBP, DE/EUR, CA/CAD, AU/AUD, SG/SGD, JP/JPY (minor_unit 0).

**FX** — `as_of = 2026-10-01`, `source = 'Illustrative static reference rates (approximate)'`. USD per unit: USD 1, EUR 1.10, GBP 1.30, INR 0.0115, CAD 0.73, AUD 0.66, SGD 0.76, JPY 0.0067.

**Departments → job titles** (~25 titles). Finalise the list in code along these lines:
- Engineering — Software Engineer, Senior Software Engineer, Staff Engineer, Engineering Manager, QA Engineer, DevOps Engineer
- Product — Product Manager, Senior Product Manager, Product Designer
- Data — Data Analyst, Data Scientist
- Sales — Sales Development Rep, Account Executive, Sales Manager
- Marketing — Marketing Specialist, Marketing Manager
- Customer Success — Support Specialist, Customer Success Manager
- Finance — Accountant, Financial Analyst, Finance Manager
- People — HR Generalist, Recruiter, HR Manager
- Operations — Operations Analyst, Office Manager

## 4. Seed (`pnpm db:seed`)

- **Deterministic.** Use `@faker-js/faker` with a fixed seed (42) and a seeded PRNG for all random choices. The same seed must produce identical data on every run.
- **10,000 employees.** Country mix: IN 35%, US 20%, GB 10%, JP 8%, DE 8%, CA 7%, AU 6%, SG 6%. Use locale-appropriate faker names per country where faker supports the locale.
- **Salary generation.** Keep this in a pure, unit-tested module, `seed/salary-model.ts`:
  - Each title has a US base in USD.
  - Apply a country factor: US 1.0, GB 0.75, DE 0.75, CA 0.75, AU 0.75, SG 0.70, JP 0.60, IN 0.25.
  - Apply ±15% seeded noise.
  - Convert to local currency with the FX table.
  - Round to the nearest 1,000 local major units (10,000 for JPY).
- **Other fields.**
  - Emails: unique, `firstname.lastname.<n>@acme.test`.
  - Hire dates within the last 12 years.
  - Employment type mix: 85% full_time / 8% part_time / 7% contract.
  - ~3% terminated, with a valid `terminated_on`.
- **History.** Each employee gets 0–3 historical salary changes, chronologically consistent and ending at the current salary.
- **Performance.** Batched multi-row inserts of 1,000 rows inside one transaction. Truncate employees and salary_changes and reset the sequence first, so the seed is idempotent. Must complete in < 15 s locally.
- **Production guard.** Refuse to run when `NODE_ENV=production` unless `SEED_CONFIRM=yes`.
- **Output.** Print counts and elapsed time.

## 5. API contract (`/api/v1`)

**Envelopes**
- Success: `{ "data": ..., "meta"?: ... }`
- Error: `{ "error": { "code": string, "message": string, "details"?: unknown } }`

**Error codes**
| Code | Status |
|---|---|
| VALIDATION_ERROR | 400 (`details` = Zod-flattened field errors) |
| UNAUTHENTICATED | 401 |
| NOT_FOUND | 404 |
| CONFLICT | 409 (duplicate email, editing terminated) |
| UNPROCESSABLE | 422 (domain rule, e.g. country change without salary) |
| PAYLOAD_TOO_LARGE | 413 |
| RATE_LIMITED | 429 |
| INTERNAL | 500 (no stack traces in production) |

**Money shape**
- Local: `{ "amountMinor": number, "currency": "INR" }`
- USD figures: `amountMinor` in cents with `currency: "USD"`
- Any response containing USD figures includes `meta.fx = { asOf, source }`

### Health & auth
- `GET /health` → `{ data: { status: "ok", db: "ok" } }`. Public.
- `POST /auth/login` `{ email, password }`. On success returns 204 and sets the cookie. On failure returns 401 with a generic message. Rate-limited to 5/min/IP.
- `POST /auth/logout` → 204, clears the cookie.
- `GET /auth/me` → `{ data: { email } }`.
- Every other endpoint requires a valid session.

### Reference
`GET /reference` → `{ countries:[{code,name,currency:{code,name,minorUnit}}], departments:[{id,name}], jobTitles:[{id,name,departmentId}], fx:{asOf,source,rates:{INR:"0.0115",...}} }`

### Employees
**`GET /employees` query parameters**

| Param | Rule |
|---|---|
| `page` | ≥ 1, default 1 |
| `pageSize` | 1–100, default 25 |
| `search` | ≤ 100 chars; matches name (trigram/ILIKE), email prefix or employee code |
| `country` | country code |
| `departmentId` | id |
| `jobTitleId` | id |
| `employmentType` | enum |
| `status` | `active` (default), `terminated` or `all` |
| `sort` | `fullName` (default), `hireDate`, `salaryUsd`, `country`, `jobTitle` |
| `order` | `asc` (default) or `desc` |

Sorting always adds `id` as a tie-breaker. `salaryUsd` sorts by the USD-normalised value, because sorting raw amounts across currencies is meaningless.

Response: `data: EmployeeListItem[]`, `meta: { page, pageSize, total, totalPages, fx }`.

`EmployeeListItem = { id, employeeCode, fullName, email, jobTitle:{id,name}, department:{id,name}, country:{code,name}, salary:Money, salaryUsd:Money, employmentType, hireDate, status, terminatedOn }`

**Other employee endpoints**
- `GET /employees/:id` → `EmployeeDetail` = list item + `salaryHistory: [{ id, previous: Money|null, new: Money, effectiveDate, reason, createdAt }]` (newest first) + `createdAt`, `updatedAt`.
- `POST /employees` `{ fullName, email, jobTitleId, countryCode, salaryMinor, employmentType, hireDate }` → 201 with `EmployeeDetail`.
- `PATCH /employees/:id` → 200 with `EmployeeDetail`.
  - Body: a partial of the create fields, plus optional `salaryChange: { effectiveDate?, reason? }`. `effectiveDate` defaults to today.
  - Returns 422 if `countryCode` changes without `salaryMinor`.
  - Returns 409 if the employee is terminated.
  - A no-op salary (same value) writes no history row.
- `POST /employees/:id/terminate` `{ terminatedOn }` → 200 with `EmployeeDetail`.

### CSV
- `GET /employees/export.csv`
  - Accepts the same filters as the list.
  - Streams `text/csv` with `Content-Disposition: attachment; filename="employees-YYYY-MM-DD.csv"`.
  - Columns, in order: `employee_code,full_name,email,department,job_title,country_code,currency,salary,employment_type,hire_date,status,terminated_on`.
  - `salary` is in major units with the correct decimals (e.g. `1250000.00`; JPY `8500000`).
  - Neutralise CSV formula injection: prefix any text cell starting with `= + - @ \t \r` with `'`.
- `POST /employees/import?dryRun=true|false`
  - multipart, field `file`; ≤ 5 MB; ≤ 10,000 data rows.
  - Required headers: `full_name,email,job_title,country_code,currency,salary,employment_type,hire_date`.
  - Optional headers: `employee_code`, `department`. Other export columns (e.g. `status`, `terminated_on`) are ignored, so an exported file can be re-imported unchanged.
  - Blank `employee_code` → create. An existing code → update that employee. An unknown code → row error.
  - Per-row validation:
    - `job_title` must match a title name (case-insensitive).
    - `department`, if present, must match the title's department.
    - `currency` must equal the country's currency.
    - `salary` must have no more decimals than the currency exponent.
    - `hire_date` must be ISO `YYYY-MM-DD`.
    - Duplicate emails within the file are errors, as are email conflicts with other employees.
    - Updating a terminated employee is an error.
  - **All-or-nothing:** if any row has an error, nothing is written. Otherwise everything is applied in one transaction. Salary changes get history rows with reason `"CSV import"` and today's effective date.
  - Response: `{ data: { dryRun, totalRows, toCreate, toUpdate, unchanged, errors: [{ row, field?, message }] } }`. `row` is the 1-based line number including the header. Status is 200 even when `errors` is non-empty; 400 only for a malformed file or missing headers.
  - CSV parsing and row validation are **pure functions**, unit-tested without a DB.

### Insights (active employees only; optional `employmentType` filter on all)
- **USD conversion per employee:** `salary_minor / 10^minor_unit * usd_per_unit * 100` → cents. Compute it in a CTE, then aggregate.
- **Median** = `percentile_cont(0.5)`.
- **Averages and medians** are rounded to integer minor units.

| Endpoint | Returns |
|---|---|
| `GET /insights/summary` | `{ activeHeadcount, countryCount, totalPayrollUsd, averageSalaryUsd, medianSalaryUsd }` |
| `GET /insights/by-country` | per country: `{ country, currency, headcount, min, max, average, median (local Money), averageUsd, medianUsd }`, sorted by headcount desc |
| `GET /insights/by-country/:code` | `{ country, currency, summary:{headcount,min,max,average,median}, jobTitles:[{jobTitle, department, headcount, min, max, average, median}], distribution:[{ fromMinor, toMinor, count }] }`. Distribution uses 10 equal-width buckets between the country min and max via `width_bucket`; the top value goes into the last bucket. |
| `GET /insights/by-job-title/:id` | the same role compared across countries: `[{ country, headcount, average, median (local), averageUsd, medianUsd }]` |
| `GET /insights/by-department` | `[{ department, headcount, averageUsd, medianUsd, minUsd, maxUsd }]` |

All insight queries must be single SQL statements per endpoint. Do no aggregation in JS over full employee lists.

## 6. Auth & security

- **Credentials.** A single HR user comes from env: `HR_EMAIL` and `HR_PASSWORD_HASH` (bcrypt, cost 12). Provide the script `pnpm --filter api hash-password '<pw>'`. Compare with `bcrypt.compare`, and always run a compare (against a dummy hash if the email mismatches) to avoid timing leaks.
- **Session.** HS256 JWT signed with `SESSION_SECRET` (≥ 32 chars, validated at boot), `sub=email`, expiry 8h. Store it in cookie `acme_session`: `HttpOnly; SameSite=Lax; Path=/; Secure` in production.
- **Same-origin by design.** The browser only ever talks to the Next.js origin. `next.config` rewrites `/api/:path*` → `${API_ORIGIN}/api/:path*`. This keeps the cookie first-party and avoids third-party-cookie blocking, so no CORS configuration is needed. Document this in an ADR.
- **CSRF.** Mutating routes require `Content-Type: application/json` (except import, which is multipart) and reject requests whose `Origin` header is present and not in `ALLOWED_ORIGINS`.
- **Hardening.** helmet; `app.set('trust proxy', 1)`; JSON body limit 100 kb; the pino redaction list includes `password`, `cookie` and `authorization`.
- **Web guard.** `middleware.ts` in the web app redirects to `/login` if the cookie is absent. The API remains the real enforcement point; the client redirects to `/login` on any 401.
- **API env**, validated with Zod at startup (fail fast): `DATABASE_URL, HR_EMAIL, HR_PASSWORD_HASH, SESSION_SECRET, ALLOWED_ORIGINS, NODE_ENV, PORT, LOG_LEVEL`.
- **Web env:** `API_ORIGIN`.
- Commit `.env.example` files only.

## 7. Backend architecture

```
apps/api/src/
  app.ts                # createApp(deps) — pure wiring, no listen(); used by tests
  server.ts             # loads env, builds deps, listens, graceful shutdown
  config/env.ts
  db/ (client.ts, schema.ts, migrate.ts, migrations/, seed/)
  lib/ (errors.ts, http.ts [envelope + asyncHandler], logger.ts, money.ts → re-export shared)
  middleware/ (auth.ts, error-handler.ts, validate.ts, origin-check.ts)
  modules/
    auth/        routes, controller, service, *.test.ts
    reference/   routes, controller, repository
    employees/   routes, controller, service, repository, types, *.test.ts
    insights/    routes, controller, repository, *.test.ts
    csv/         export.ts, import-parser.ts (pure), import-service.ts, *.test.ts
```

- **Layering:** routes → controller (HTTP only) → service (domain rules, transactions) → repository (SQL only).
- **Dependency injection** through factory functions (`createEmployeeService({ employeeRepo, referenceRepo, clock, db })`). A **`clock` dependency** keeps "today" deterministic in tests.
- **Services depend on repository interfaces.** Unit tests use hand-written in-memory fakes; do not use a mocking library for repositories.
- Use `db.transaction()` for any multi-table write.
- **Graceful shutdown:** on SIGTERM, close the server, then the pool.

### Screens

**Login.** Email and password fields, error state, and a redirect back to the requested page.

**Employees list**
- Server-side table using TanStack Table in manual mode.
- Columns: code, name, job title, department, country, salary (local, formatted with `Intl.NumberFormat` and the correct currency), ≈ USD (muted, with tooltip), type, hire date, status badge.
- Filter state is held in URL params via nuqs, so views are shareable and survive refresh. Search input is debounced by 300 ms.
- Pagination shows the total.
- Actions: Add employee, Export CSV (current filters), Import.
- Loading skeletons, an empty state, and an error state with retry.

**Employee form** (create and edit)
- Uses the shared Zod schemas.
- Salary is entered in major units. The label shows the currency, and the label updates when the country changes.
- Shows a warning when the country is changed: "currency will change — enter salary in X".
- On edit, a salary change reveals optional effective date and reason fields.
- Server errors map back to the corresponding fields.

**Employee detail**
- Summary card.
- Salary history timeline showing previous → new, % change when the currency is unchanged, effective date and reason.
- Terminate action with a confirm dialog and date.
- Terminated employees are shown read-only.

**Insights**
- Summary stat cards.
- "By country" table (local min/max/avg/median plus avg USD) with a bar chart of average and median USD by country.
- Country drill-down via a select: job-title table and distribution histogram.
- "Compare a role across countries" via a select.
- Department chart.
- A persistent FX disclaimer showing `asOf`.

**Import**
1. Upload the CSV.
2. Run a dry-run and show a summary (create / update / unchanged) plus an error table (row, field, message).
3. The "Apply import" button is enabled only when there are 0 errors.
4. Show the result and invalidate queries.

Also offer a downloadable template CSV with headers and a few example rows.

**Across the app**
- Toasts for mutations.
- Accessible labels and keyboard navigation (shadcn defaults).
- Responsive down to tablet width.

## 12. Decision log → `docs/adr/`

Write one short ADR per decision (context, decision, consequences, alternatives considered):
1. Monorepo with a shared Zod contract package
2. Kysely over Prisma/Drizzle (explicit SQL for aggregates, no codegen engine, transactions)
3. Money as integer minor units + currency exponent table
4. Currency derived from country, enforced by a composite FK
5. Static dated FX table instead of live rates
6. Salary history as an append-only table written transactionally
7. Soft termination instead of delete
8. Single-user auth: JWT in an httpOnly cookie behind a same-origin Next.js proxy
9. Offset pagination (fine at 10k; keyset noted for scale)
10. Plain SQL aggregates instead of pre-aggregation/caching
11. CSV import: all-or-nothing with dry-run, upsert by employee_code
12. Testing pyramid: fakes for services, Testcontainers for SQL

## 13. Acceptance criteria

1. `docker compose up -d && pnpm install && pnpm db:migrate && pnpm db:seed && pnpm dev` runs the full stack locally from the README instructions alone.
2. The seed creates exactly 10,000 employees deterministically across 8 countries.
3. Unauthenticated requests to protected API routes return 401, and protected pages redirect to `/login`.
4. The list supports search, every filter, every sort, pagination, and shareable URLs.
5. Create, edit and terminate all work. Invalid input shows field errors. A duplicate email gives 409. Changing country without a salary gives 422.
6. Every salary change appears in history, including changes made by import.
7. All insights endpoints return correct numbers, as verified by integration tests against hand-computed fixtures.
8. USD figures are always labelled approximate and carry the FX `asOf` date.
9. Export → re-import of the same file results in 0 creates, 0 updates and N unchanged. An edited salary shows as 1 update.
10. A CSV with one bad row writes nothing and reports the row and field.
11. Formula-injection characters are escaped on export.
12. JPY salaries are handled correctly end to end (no decimals).
13. Lint, typecheck and all test suites pass, and CI is green.
14. Performance numbers are measured and recorded.
15. All docs and artifacts listed in the implementation prompt exist and are accurate.
