# Trade-offs and deviations

This file records (1) the key trade-offs behind the design and (2) every place where the build
deviates from, or fills a gap in, `docs/SPEC.md`. The SPEC itself is never edited.

## Deviations and gap-filling decisions made during the build

| #   | Topic                                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                                                                                                                                 |
| --- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | TypeScript version                      | Pinned to TypeScript **6.0.x**, not the newest 7.0.                                                                                                                                                                                                                                                                                                                                                                                                         | `typescript-eslint` (required by SPEC §1) supports TypeScript `<6.1.0` only. Lint is a CI gate, so the compiler follows the linter.                                                                                                                                 |
| D2  | Local DB port                           | docker compose publishes Postgres on host port **5434** (overridable with `ACME_DB_PORT`).                                                                                                                                                                                                                                                                                                                                                                  | 5432 and 5433 are commonly taken by other local Postgres instances; a fixed non-default port keeps `docker compose up` working out of the box.                                                                                                                      |
| D3  | Local env loading                       | `pnpm dev`, `db:migrate` and `db:seed` load `apps/api/.env.example` and then `apps/api/.env` via Node's `--env-file-if-exists`. `pnpm start` (production) loads no file.                                                                                                                                                                                                                                                                                    | Makes the SPEC §13.1 command (`docker compose up -d && pnpm install && pnpm db:migrate && pnpm db:seed && pnpm dev`) work with no copy step. The example file holds only local-only values; production must set real env vars, and env validation still fails fast. |
| D4  | Job titles                              | The reference migration inserts all **26** titles listed in SPEC §3 (the SPEC says "~25").                                                                                                                                                                                                                                                                                                                                                                  | The SPEC's own list has 26 entries; dropping one would be arbitrary.                                                                                                                                                                                                |
| D5  | DATE parsing                            | `pg` is configured to return `DATE` columns as `YYYY-MM-DD` strings (SPEC only specifies BIGINT and NUMERIC).                                                                                                                                                                                                                                                                                                                                               | pg's default turns DATE into a local-midnight JS `Date`, which shifts days across timezones.                                                                                                                                                                        |
| D6  | Seed names for Japan                    | Japan uses a curated list of common romanised given/family names instead of faker's `ja` locale. Singapore uses faker's generic `en` locale (faker has no `en_SG`).                                                                                                                                                                                                                                                                                         | Faker's `ja` names are kana/kanji, which cannot form the ASCII `firstname.lastname.<n>@acme.test` emails the SPEC requires.                                                                                                                                         |
| D7  | Seed "today"                            | The seed uses a fixed reference date (`2026-10-01`, the FX `as_of` date) for hire dates, terminations and history.                                                                                                                                                                                                                                                                                                                                          | SPEC §4 requires identical data on every run; anchoring to the real clock would change the data set daily.                                                                                                                                                          |
| D8  | Seed country mix                        | Per-country counts are allocated exactly (IN 3,500, US 2,000, …) and then shuffled, rather than sampled at random.                                                                                                                                                                                                                                                                                                                                          | Gives exactly the SPEC percentages and still interleaves countries across employee codes.                                                                                                                                                                           |
| D9  | Initial history reason                  | The initial `salary_changes` row written at hire carries the reason `"Initial salary"` (seed and API).                                                                                                                                                                                                                                                                                                                                                      | The SPEC fixes `previous = null` but not the reason; a label reads better in the history timeline than an empty value.                                                                                                                                              |
| D10 | `FORBIDDEN` error code                  | Added `FORBIDDEN` (403) to the error codes; used only when a mutating request carries an `Origin` outside `ALLOWED_ORIGINS`.                                                                                                                                                                                                                                                                                                                                | SPEC §6 requires rejecting such requests but §5's code table has no fitting code; 401/400 would mislabel a CSRF rejection. A wrong `Content-Type` uses the existing `VALIDATION_ERROR` (400).                                                                       |
| D11 | No `asyncHandler`                       | `lib/http.ts` has the envelope helper only.                                                                                                                                                                                                                                                                                                                                                                                                                 | Express 5 forwards rejected promises from async handlers to the error handler natively, so an `asyncHandler` wrapper (SPEC §7) would be dead code.                                                                                                                  |
| D12 | Cookie parsing                          | A 10-line `readCookie` helper instead of `cookie-parser`.                                                                                                                                                                                                                                                                                                                                                                                                   | Only one cookie is ever read; avoids a dependency outside SPEC §1.                                                                                                                                                                                                  |
| D13 | Validation middleware shape             | `validate(schemas, handler)` parses params/query/body and passes typed values to the handler.                                                                                                                                                                                                                                                                                                                                                               | Express 5 makes `req.query` read-only, and passing parsed input as an argument keeps handlers fully typed without casts.                                                                                                                                            |
| D14 | Unknown API routes                      | Routes under `/api/v1` that do not exist return 401 without a session and 404 with one.                                                                                                                                                                                                                                                                                                                                                                     | The session guard runs before route matching so the API never reveals which routes exist to anonymous callers.                                                                                                                                                      |
| D15 | Salary-change effective date            | An explicit `salaryChange.effectiveDate` must fall between the hire date and today (422 otherwise).                                                                                                                                                                                                                                                                                                                                                         | The SPEC defaults it to today but sets no bounds; future-dated changes are listed as future work (docs/FUTURE.md), and a change before the hire date is meaningless.                                                                                                |
| D16 | Domain field errors                     | Domain-rule failures that concern one field (unknown country or job title, salary limit, hire date, effective date, termination date, country change without salary) return 422 with `details` in the same `{ formErrors, fieldErrors }` shape as Zod validation errors. Duplicate email returns 409 with the same shape.                                                                                                                                   | Lets the web form map every server error to its field with one code path, while keeping the SPEC's status codes.                                                                                                                                                    |
| D17 | Transactions in the service             | The employee service receives a `transaction(work)` runner (a repository bound to a DB transaction) instead of the raw `db`.                                                                                                                                                                                                                                                                                                                                | Keeps services free of Kysely so unit tests use the in-memory fake (whose runner restores a snapshot on failure), while production still uses `db.transaction()`.                                                                                                   |
| D18 | List sort direction for the tie-breaker | The `id` tie-breaker follows the requested `order`.                                                                                                                                                                                                                                                                                                                                                                                                         | Keeps pages stable in both directions; the SPEC only requires that `id` is always added.                                                                                                                                                                            |
| D19 | Insight rounding                        | Per-employee USD values stay unrounded NUMERIC inside the CTE; only aggregates (sum, average, median, min, max) are rounded to whole cents.                                                                                                                                                                                                                                                                                                                 | Rounding each employee first would let rounding error accumulate in totals; rounding once is closer to the true figure.                                                                                                                                             |
| D20 | Insights ordering and edge cases        | `by-country` and `by-department` are ordered by headcount (then name), `by-job-title/:id` by average USD (highest first), country job titles by headcount then title. A country whose active salaries are all equal returns a single distribution bucket; a valid country with no active employees returns zero amounts and empty lists. `by-job-title/:id` checks the title exists through the reference repository before the single aggregate statement. | The SPEC fixes the shapes but not the order or the degenerate cases; `width_bucket` cannot build buckets over a zero-width range.                                                                                                                                   |
